적용

  1. 모바일 크기 안정화. 최초 화면은 바로 표시합니다. 이후 실제 CSS 크기가125ms 안정되면 반영하며, 연속 변화도500ms 안에 최신 크기를 반영합니다. 데스크톱 크기 조절은 다음 프레임에 반영합니다. 같은 크기의180도 회전은 안전영역 UI만 갱신합니다.
  2. 회전과 새 텍스처 작업 분리. 지연된 회전 레이아웃을 확인하는 동안 새 고해상도 작업과 아직 시작하지 않은 디코딩, 완성된 텍스처의 교체를 기다립니다. 이미 시작한 디코딩은 취소·재다운로드하지 않습니다. 한 작업 예약과 기존 메모리 예산을 유지하며, 해제·컨텍스트 유실·시간 초과에는 소유한 대기만 정리합니다.
  3. 첫 보상 표시 준비. 기존3개 코인의 재질·공유 지오메트리를 로딩 화면 뒤에서 준비합니다. 같은 장면의 조명·안개가 바뀌면 해당 변형을 다시 확인합니다. 준비용 코인은 화면에 그리지 않고 제거합니다. 보상 수량·모양·획득 시점은 유지합니다.
  4. 진단 범위 보완. framePreludeMs와 sceneCallMs를 추가했습니다. 후자는 모든 후처리 관찰자까지 포함한 scene.render 호출입니다. 상세 CPU 계측은 기본OFF이며, 선택했을 때만 사망·크기 반영·텍스처 교체 다음 렌더를 이유와 함께 표본으로 남깁니다. 이벤트 표본은250ms 이상 간격이고 대기는 한 칸으로 합칩니다.
