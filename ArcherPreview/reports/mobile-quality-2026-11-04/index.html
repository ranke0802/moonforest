메모리 값은 텍스처의 해상도·압축 블록·밉맵으로 계산한 추정치입니다. 전체 GPU 메모리 실측이나 FPS·발열 개선 수치가 아닙니다. 모바일 기본85%는 화면 픽셀 수가 기존의72.25%, 75% 옵션은56.25%가 됩니다. 성능 향상률은 병목에 따라 다릅니다.

호환성과 자원 관리

  • 최대 크기4096 이상 + GPU 압축 형식 지원 시 플레이어4K 프로필 하나를 선택합니다.
  • 압축 미지원 또는 최대 크기2048~4095이면2K 비압축 프로필을 사용합니다. 더 낮거나 확인 불가이면 실제 최대 크기와 형식 지원 정보를 포함한 오류를 표시합니다.
  • ASTC만 지원할 때 ETC1S가 비압축으로 풀리는 경우까지 실제 디코더 결과와 비교해 메모리를 예약합니다.
  • 일반 풍경은 모바일에서만1K/2K 대체 파일을 사용합니다. 집·예배당·마을 외관 프리팹과 보스는 원본 프로필을 사용합니다. 데스크톱은 기존 프로필을 유지합니다.
  • 기존 업로드 직렬화·이동 중 간격·체류시간·메모리 예산·취소·재시도 정책을 유지합니다. 원본과 모바일 파일을 한꺼번에 내려받지 않도록 선택 계획을 검증했습니다.

CPU 개선 범위

외곽선 준비에서 같은 source/LOD 등록을 배치 안에서 공유하고, 그림자 상태가 같을 때 동일한 caster 집합과 속성 제출을 재사용합니다. 네 맵90개 실제 packed 모델과200회 native main/shadow 배치 비교에서 동등성을 확인했습니다. 로딩 중 source 준비 횟수는 마을2211→64, 대평원3194→40, 숲2670→27, 동굴293→30입니다. CPU 시간 이득은 작은 Node 참고값이며 모바일 FPS 개선으로 환산하지 않았습니다.

먼 풍경의 선·그림자는 이미 거리·화면 점유율·예산에 따라 제한됩니다. 이번에는 기존 제한을 유지하면서 중복 준비·제출을 줄였습니다. 일반 풍경에는 별도 내부선 패스를 추가하지 않았습니다.

검증

  • 전체 자동 검사: 1790 / 1790 통과.
  • 집·보스 보호 대상10개: content147파일·텍스처38개와 별도 원본 보스2파일의 해시 보존.
  • 플레이어4K 이미지6개 × 압축 경로4종의24개 변환 검사와 배경의61개 디코더 사례 검사.
  • 선택 프로필48경우, 배경 대체 프로필65개, 새 자원96개의 해시·용량·다운로드 계획 확인.
  • 맵 왕복·캐시·타임아웃 후 재시도·늦은 완료·전투·사망·리스폰·컷씬·배치 도구 관련 기존 회귀 검사 포함.
  • 처음 검사에서 발견된 과거8K 기대값과 원본 manifest 전체 해시 검사는 새 정책에 맞춰 갱신했습니다. 원본 geometry/텍스처 historical SHA는 유지하고 모바일 추가 필드를 별도로 검증합니다.

브라우저 자동조작은 사용하지 않았습니다. 실제 Y700·S23의 GPU 업로드, 화면 사용감, 지속FPS와 온도는 확인하지 못했습니다. 60FPS나 발열 문제가 해결됐다고 단정하지 않습니다.

사용 방법

MoonForest 0.1ver에서 설정 → 화면·카메라 → 3D 해상도를 선택합니다. 모바일 기본85%이며 성능 우선은75%, 선명도 우선은100%입니다. UI 글자·버튼 크기와 FPS 선택은 독립적으로 유지됩니다. 선택은 재접속과 맵 이동 후에도 저장됩니다.
