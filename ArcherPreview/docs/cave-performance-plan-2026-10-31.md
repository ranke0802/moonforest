# 마녀의 동굴 성능·품질 개선 계획

기준 게임: 전사 v5, 배포 코드 `618c7408657c8e6017e87c3e72fc43f6d902de57`. 기존 마을·숲·동굴과 전사/보스 기능을 유지한다. 플레이어 8K, 배경 최대 4K, 기존 LOD, 외곽선·그림자·모션 품질을 유지하고 새 에셋 생성이나 브라우저 자동조작은 하지 않는다. 추가 배치는 보유 에셋을 재사용한다.

## 1. 기준 측정 및 진단

- 동일한 위치·카메라·설정에서 전투 전, 각 보스 소환 직후와 전투 중, 처치 직후 및 이후를 구분해 기록한다. 최소 10~20분 재소환·맵 왕복을 포함한다.
- 기존 프레임 시간·드로콜·CPU 구간·JS 메모리 진단을 활용하고, 기기와 브라우저가 지원하는 경우에만 GPU 시간 측정을 검토한다. 미지원·유효하지 않은 GPU 표본은 미지원으로 표시한다.
- S23 Chrome과 iPhone 14 Pro의 FPS·긴 프레임·온도 추이를 실제 기기에서 같은 조건으로 확인한다. 온도는 기기에서 얻을 수 있는 방법으로 별도 기록하고, 브라우저에서 읽을 수 있다고 가정하지 않는다. 실기기 조작과 최종 화면 검수는 사용자가 한다.
- **완료 기준:** 측정 조건과 미지원 항목을 기록하고, 전투 중과 처치 후 어느 구간에 비용이 남는지 전후 비교 가능하게 제시한다. CPU 시간·JS 힙을 GPU 시간·전체 메모리로 표기하지 않는다.

## 2. 소환·변신 준비 분산

- 보스 모델 준비, 외곽선 생성, 애니메이션·경계 계산과 셰이더 준비 중 실제 긴 작업을 분리해서 측정한다. 데스크톱에서 확인된 약 55ms 일회성 준비는 모바일 수치가 아니므로 현장 측정으로 우선순위를 확인한다.
- 효과가 확인된 작업은 전투 시작 전 준비하거나 프레임 단위로 나눈다. 중단·맵 이동·재소환 시 중복 객체, 불완전한 모델 노출, 중복 다운로드가 없도록 한다.
- **완료 기준:** 같은 조건에서 준비 단계의 최장 프레임과 소환 지연을 이전과 비교하고, 변신·재시작·맵 왕복·캐시 재사용 검사를 통과한다.

## 3. 타락한 성녀의 화면 밖 처리

- 비탄의 마녀에 적용된 보수적인 스킨·모프 경계 방법을 성녀에 적용할 수 있는지 실제 모델 데이터로 검사한다. 현재 모델 계약에 맞지 않는 경우에는 기존 그리기로 되돌린다.
- 본체와 외곽선만 화면 밖에서 제외하며 화면에 보일 수 있는 그림자는 유지한다. 모든 공격·이동·피격·전환 자세와 외곽선 화면 경계, 반복 재소환을 검사한다.
- **완료 기준:** 실제 애니메이션 정점이 경계에 포함되고, 회전·이동 시 모델 누락/깜빡임과 그림자 누락이 없어야 한다. 제외한 제출량과 추가 CPU 비용을 함께 보고한다.

## 4. 화면을 채운 비탄의 마녀

- 몸·외곽선·그림자가 동일한 스킨/모프 변형을 반복하는 비용을 측정한다. 변형 결과 공유 등은 실험으로만 시작하고, 추가 메모리와 준비 비용도 비교한다.
- 얼굴·손·기도 팔·천·후광·사망 및 공격 보정 모프를 보존한다. 양면 재질을 일괄 제거하거나 해상도·LOD·그림자 갱신을 임의로 낮추지 않는다.
- **완료 기준:** 실제 기기의 프레임 시간 개선과 외형/동작 보존을 둘 다 확인한 방식만 채택한다. 개선이 불확실하거나 품질이 떨어지면 기존 경로를 유지한다.

## 5. 동굴 카메라와 마감

- 좁은 아치, 벽 모서리, 최대 줌·위쪽 시야, 회피 중 회전에서 카메라가 갑자기 확대되거나 캐릭터를 가리는지 검수한다. 벽·천장 관통 방지를 유지하며 움직임을 보정한다.
- 기존 암벽·바위·수로 에셋을 사용해 평평한 연결면과 반복 실루엣을 개선한다. 통로·수로·5.7m 보스의 이동/공격 공간은 유지한다.
- **완료 기준:** 카메라·충돌·시야·보스 전신 여유 표를 변경된 배치에 맞게 갱신하고, 기존 동선과 돌진·회피·마법 판정을 검사한다. 최종 화면은 실기기에서 확인한다.

## 6. 통합 검증과 배포

- 전사 8K, 배경 최대 4K, LOD와 원본 리깅·모프·외곽선·그림자 설정, 두 단계 전투, 소환/사망/재시작, 마을·숲·동굴 왕복, 캐시를 회귀 검사한다.
- 전후 FPS·프레임 지연·드로콜·측정 가능한 메모리와 준비 시간, 미측정 항목을 보고한다. 디바이스의 발열 개선은 직접 측정한 경우에만 수치로 주장한다.
- 기존 JSON 콘텐츠 해시와 묶음 절차를 사용해 변경된 리소스만 갱신한다. 전체 자동검사 → 빌드 → 배포 파일 검증 → `archer` 배포 → 공개 파일 검증 순서로 진행한다. 다른 작업 채팅의 완료된 모델을 통합할 때는 공유 인계 파일과 현재 변경 사항을 먼저 대조한다.

우선순위는 **1 → 2 → 3 → 4 → 5 → 6**이다. 항목 4는 측정 결과에 따라 보류할 수 있으며, 실기기 검수 없이 모바일 발열·최종 시각 품질의 완료를 확정하지 않는다.
