MOONFOREST 기능 보존 최적화 검증 프롬프트

역할과 목표
현재 배포된 전사 v3(마을), v4(마물의 숲), v5(마녀의 동굴)를 함께 검증한다.
다운로드, 모델/화면 준비, 이동·회전 중 프레임 부하, 맵 왕복 메모리를 점검하고,
동일한 기능과 화면 결과를 유지하면서 불필요한 계산·할당·잔존 참조만 줄인다.
먼저 Git 기준 커밋, 리소스 JSON revision, 다른 에이전트 작업 범위를 기록한다.

변경하면 안 되는 기준
1. 플레이어 8K, 배경 최대 4K, 기존 근거리 메시와 3단계 LOD를 유지한다.
   해상도, 렌더 배율, FPS 상한, 시야 범위, 그림자/외곽선 품질을 낮춰 얻는 개선은 제외한다.
2. 카툰 셰이딩, PBR 효과 해제, 그림자·외곽선, 나무/지형/배치와 포탈 연무를 유지한다.
3. 전체화면·기기 방향, 턱 중심 카메라, 줌 배율/최소·최대 설정, 조작 UI를 보존한다.
   포탈 이동 시 같은 문서의 scene/engine/player/camera를 유지하고 체력·물약·장비를 보존한다.
4. 이동·공격·방패·회피·물약·장비 교체·곰 잡기 탈출 1초·사망/재시작·골드 기능을 바꾸지 않는다.
5. 추가 원화/모델 생성, 브라우저 자동조작, 전체화면 자동 진입을 하지 않는다.
   확인할 수 없는 GPU 화면·S23 발열·실제 FPS는 미검증으로 명시한다.
6. 기존 미커밋/다른 에이전트 변경을 건드리지 않는다. 게시 경로는 선별한다.
   네트워크 오류/승인 차단은 반복 재시도하지 않고 원인과 중단 범위를 보고한다.

검증 순서
A. 코드와 README/정책 문서를 비교해 오래된 지침, 중복 작업, 객체 수명 문제를 찾는다.
B. 데이터와 성능 기준을 먼저 수집한다. CPU 측정은 같은 PC/Node에서 워밍업 후
   여러 표본의 중앙값/상위 백분위를 사용한다. 첫 생성과 캐시 재방문을 구분한다.
   부하를 줄였다는 근거로 계산 횟수·할당량·잔존 참조·요청 수를 함께 기록한다.
C. 다음 시나리오를 코드·Node/NullEngine 자동테스트로 검증한다.
   - 최초 접속, 캐시 재접속, 부분 캐시, 한 파일 갱신, 취소/실패/저장공간 거부.
   - JSON의 해시·크기·묶음 목록, 변경 없는 파일 재사용, 구버전 탭 캐시 보호.
   - S23 가로/세로 조건에서 이동·360도 회전·확대/축소·지연 LOD 승격.
     보이는 메시/그림자/외곽선 누락, 부분 인덱스 출력, 반복 업로드를 검사한다.
   - 마을↔숲↔동굴 왕복, 장비/몬스터 등 객체 생성·폐기 반복.
     scene/material/texture/geometry/observer 수와 캐시 한도가 안정되는지 확인한다.
   - 초기 로딩 차폐·진척도, 진단 UI, 설정/탭 숨김 시 일시 정지 및 정상 복귀.
   - 카메라 배율·제한 해제/저장, 포탈의 방향 연속성, 전투·이동·충돌 회귀.
D. 재현한 문제만 최소 수정한다. 새 캐시는 항목/바이트 상한과 상태 격리를 갖춘다.
   계산 최적화는 기존 결과와 동일함을 증명한다. CPU와 GPU 비용을 혼동하지 않는다.
   시간 기반 테스트의 임의 기준을 완화해 통과시키지 않는다.
E. 관련 테스트와 전체 회귀 테스트를 수행한다. 새 변경/실패가 없으면 반복 실행하지 않는다.
   현재 build:village → sync:village → stage-pages 경로로 JSON/묶음과 게시 파일을 검증한다.
   로직/UI만 바뀌면 리소스 revision과 콘텐츠 URL이 그대로인지 확인한다.
F. 검증된 변경만 기존 배포 절차로 게시하고, 결과와 향후 점검 방법을 README에 남긴다.

결과 형식
기준 커밋/리소스 revision, 검증 명령·로그, 발견 원인, 수정 파일, 전후 수치,
기능·화질 보존 근거, 배포 상태를 기록한다. 통과/실패/미검증을 분리한다.
실기기 없이 “발열 해결”, “GPU 메모리 실측”, “S23 FPS 보장”이라고 결론 내리지 않는다.
변경할 필요가 없는 항목은 유지하고, 부작용 가능성이 큰 후보는 적용하지 않고 이유를 적는다.
