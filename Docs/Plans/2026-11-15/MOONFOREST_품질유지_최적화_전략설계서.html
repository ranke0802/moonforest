01 · 판단과 범위

먼저 줄일 것은 불필요한 상주와 반복 작업

이 게임의 다음 최적화는 같은 외형과 동작을 만들 때 필요한 자원과 작업을 통제하는 것이다. 텍스처 해상도·모델 실루엣·기존 LOD를 일괄 낮추는 작업은 이번 계획에서 제외한다.

이번 자료로 확정할 수 있는 것

PC 전사의 큰 비압축 텍스처와, 코드에 남은 별도 후보 순회·자원 교체 후속 작업은 개선 대상으로 삼을 근거가 있다. 반면 최신 로그는 200ms급 멈춤이나 몬스터 전투 병목을 재현하지 않았다. 메모리 절감만으로 모든 끊김이 해결된다고 약속하지 않는다.

유지할 품질 계약

  • PC 전사 8K 원본과 현재 승인된 외형을 보존한다. 모바일은 현행 4K 압축 / 미지원 시 2K 폴백을 기준으로 기록하며 추가 축소하지 않는다.
  • 집·보스 텍스처, 기존 배경 텍스처 최대 4K, 모델·UV·실루엣과 현재 LOD 단계·거리·대평원 240%를 유지한다.
  • 카툰 셰이딩, PBR 반사 외형 끄기, 외곽선·내부선, 상자 등급별 색·굵기, 동굴 밝기와 랜턴을 유지한다.
  • 공격 창·타점·피해·경직·제압 탈출·이동과 카메라 입력은 변경하지 않는다.

설계서의 범위

  • 확인된 구현, 정량 추정, 미확정 원인, 앞으로의 작업을 각각 표시한다.
  • 0.2를 작업 대상으로 한다. 0.1 동결 파일과 공유 리소스 그래프는 보존한다.
  • 현재 문서는 전략 산출물이다. 런타임 개선이 적용되었다는 뜻은 아니다.
  • 현재 자료와 코드로 먼저 진행 가능한 일을 정의한다. 사용자의 추가 로그·검수를 첫 작업의 착수 조건으로 삼지 않는다.

04 · 중복 작업 금지

이미 적용된 최적화 위에 남은 낭비를 줄인다

현재 적용됨다시 제안하지 않을 작업남은 설계
정적 풍경 네이티브 인스턴싱·월드 행렬 고정“모든 나무에 인스턴싱을 새로 도입”기존 공유 구조를 유지하고 여러 시스템이 별도로 계산하는 후보·투영 정보만 공유한다.
활성 후보 레지스트리·이벤트·캐시“매 프레임 Scene 전체 재검색을 처음 없애기”비활성 후보의 반복 방어 검사와 외곽선·텍스처 별도 순회를 구분해 줄인다.
공간 기반 지오메트리 수요·정지 카메라 캐시“LOD 거리 줄이기 / 공간 인덱스 새로 만들기”자산별 완료 상태·record 목록을 세대 캐시로 관리한다.
풍경 외곽선은 실제 본체 인스턴스 배치를 재사용“풍경 외곽선 메시를 일괄 삭제”외곽선 선택 정책의 재계산과 바인딩을 줄이고 동일한 선을 유지한다.
순차 텍스처 준비·예약 예산·이동/회전/뷰포트 안정화 대기“모든 KTX2를 한꺼번에 로드”기존 제한을 버리지 않고 지오메트리 설치·셰이더 준비까지 통합 예산에 포함한다.
배우별 최근 두 동작 바인딩 재사용·늑대 고정 샘플러·포즈 재사용“바인딩 캐시 처음 도입 / 캐시 무제한 확대”관측된 반복 생성이 있을 때만 구조를 바꾼다. TRS 묶기 같은 변경은 별도 동등성 실험으로 분리한다.
실제 인스턴스 셰이더 사전 준비·연결 프로그램 최대 12개 유지“전체 셰이더 조합 미리 전부 컴파일”실제 사용되지만 준비에서 누락된 변형만 기존 지연 기록으로 추적한다.
KTX 작업자 1개·8초 유휴 종료·큰 이미지 별도 CPU 캐시 제외“작업자 증설 / 8K 디코딩 결과를 이중 캐시”업로드 순간 최고 메모리와 최종 상주량을 분리하고 소유권을 유지한다.
맵 이동 시 플레이어 유지·배경 교체·세대 취소“맵마다 플레이어를 다시 불러오기”공통 자원은 보존하고 맵 자원만 참조·예약·관찰자까지 해제한다.
05 · 핵심 설계

여섯 개의 독립된 개선 묶음

P1-A 텍스처의 실제 사용 범위와 선택 정책

정량 기대 있음미구현

목적: 해상도와 모델을 유지하면서 큰 비압축 상주·디코딩 임시 메모리를 줄인다.

  1. 137삼각형과 본체 이미지에서 실제 참조하는 UV 영역을 측정한다. 반복 UV·샘플 범위·공유 재질을 포함한다.
  2. 가능한 영역은 원본 화소를 리샘플링하지 않고 복사한다. UV 대응만 재작성하고 mip·비등방성 필터용 경계 여백을 만든다. 사용 차트가 넓으면 무리하게 작은 아틀라스 크기를 목표로 삼지 않는다.
  3. PC는 최대 텍스처 크기와 실제 GPU 압축 지원을 확인한 뒤 기존 8K UASTC 후보를 선택한다. 모바일 4K/2K 폴백과 별도 정책으로 관리한다.
  4. 캐시·다운로드 계획을 세우기 전에 한 프로필만 결정한다. 지원 실패 시 8K RGBA와 KTX2를 동시에 준비하거나 반복 재시도하지 않는다.
  5. 원본 이미지·원본 모델은 보존한다. 새 UV 후보는 0.2 별도 파일·hash·원본 레지스트리로 등록하고, 모든 관련 프로필의 매핑을 함께 갱신한다.

실패 기준: 얼굴·머리·갑옷의 압축 흔적, 색공간·밝기 변화, mip 이음새, 머리카락 경계·UV 왜곡이 보이면 해당 후보를 되돌린다. GPU 압축은 픽셀 무손실로 표현하지 않는다.

P1-B 풍경의 공통 후보·투영 정보

코드에서 반복 확인미구현

목적: 같은 풍경을 가시성·외곽선·고해상도 텍스처 시스템이 각각 훑고 거리를 계산하는 작업을 줄인다.

  1. 기존 공간 인덱스의 후보 결과를 카메라·맵·편집 세대가 포함된 스냅샷으로 만든다. 후보에는 거리·보수적 화면 크기·활성 상태처럼 재사용 가능한 값만 담는다.

P1-C 준비·설치·공개의 프레임 예산

기존 예산 확장순간 지연 인과 미확정

목적: 모델을 받은 뒤 한 프레임에 메시 교체·인스턴스 경계 갱신·선 준비·가림 정보 갱신이 몰리는 것을 막는다.

필요 자원 결정→다운로드·디코드→설치·버퍼·실제 셰이더 준비→준비 완료본 공개→이전 자원 해제
  1. 기존 약 3ms 작업 분할 예산을 지오메트리 설치와 후속 작업까지 확장한다. 한 프레임에 여러 준비 작업이 각자 3ms씩 실행되지 않도록 공통 예산을 제공한다.
  2. 기존 LOD는 새 LOD가 완전히 준비될 때까지 유지한다. 데이터 준비와 화면 교체를 분리하고, 공개는 한 단계로 처리한다.
  3. 맵 로딩 중에는 필요한 준비를 로딩 화면에서 끝낸다. 플레이 중에는 입력·전투보다 낮은 우선순위로 준비하며, 전투 중 필요한 자원을 굶기지 않는 우선순위도 둔다.
  4. 포즈·시각 상태가 다른 실제 변형만 사전 준비한다. 사망 fade·외곽선·그림자·인스턴스 경로의 누락을 식별하되, 이미 존재하는 사전 준비를 중복 실행하지 않는다.

중요한 한계: 하나의 WebGL 호출·드라이버 대기가 100ms를 막으면 JS 분할만으로 그 호출을 중간에 끊을 수 없다. 먼저 어떤 업로드·셰이더·드로 호출인지 연결하고, 실행 시점·재사용·할당 구조를 바꿔야 한다. finish·동기 GPU readback으로 기다려 확인하지 않는다.

P3 신규 몬스터·NPC·컷씬의 추가 비용 계약

확장 기준

목적: 텅 빈 맵에 맞춘 최적화에서 끝나지 않고, 전투·연출이 추가돼도 비용이 예측 가능하게 한다.

  • 몬스터는 사용자가 계획한 1만~5만 삼각형을 전제로 한다. 모델 수 외에도 primitive·재질·뼈·morph·선·그림자·동시 화면 점유율을 등록한다. 새 수치가 현행 승인 자산을 자동 감량하는 명령이 되지 않게 한다.
  • 지오메트리·텍스처·모션 데이터는 공유하고, Skeleton·동작 시간·블렌드·AI·피격 상태는 개체별로 보유한다. 숨은 풀은 무한히 선점하지 않는다.
  • 교전 개체의 포즈·타격·제압 탈출 시간은 정확히 갱신한다. AI·충돌 주기를 일괄 낮추지 않는다. 화면 밖 시각 포즈 생략은 판정에 쓰지 않는 개체에만 별도 증명 후 적용한다.
  • 근접 일반 몬스터는 늑대·여우·멧돼지처럼 체형별 실제 접촉을 유지한다. 행렬·샘플 결과를 같은 프레임에 재사용해 계산을 줄인다.
  • 소환 20마리 설정은 기능 상한이며 20보스 동시 60FPS 보장이 아니다. 5/10/20 일반 개체와 보스 혼합을 별도 프로필로 구분한다.
  • 컷씬은 파일 로더와 기존 scene·공유 자원을 사용한다. 다음 샷의 실제 배우·모션·재질만 먼저 준비하고, 카메라·입력·효과 소유권을 종료 때 복구한다. 곰 샘플 컷씬을 게임 콘텐츠로 자동 추가하지 않는다.
  • 향후 낮밤·날씨는 공용 환경 파라미터로 연결한다. 재질마다 새 타이머·광원·렌더 타깃을 만들지 않고 현재 선·카툰·그림자 계약 안에서 별도 비용을 기록한다.

낮은 우선순위 실험: 네이티브 플레이어 TRS 세 채널 묶기 등은 포즈·블렌드·이벤트 동등성이 확보될 때만 진행한다. 현행 바인딩 캐시를 다시 만드는 작업으로 시작하지 않는다.
