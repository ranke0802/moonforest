# v4.19 · 한글 이름 입력 확정

## 원인과 변경

v4.18은 조합 중인 마지막 글자를 저장용 캐시에만 보관했다. 실제 macOS 두벌식으로 `ㅇㅇ` 입력 → 직업 선택 → 이름 칸 재클릭 → `ㅇ` 추가를 수행하면, 화면 편집기에는 `ㅇ`만 남아 최종 이름도 기대한 `ㅇㅇㅇ` 대신 `ㅇㅇ`으로 저장됐다. 직후 시작 버튼을 누르는 검사만으로는 이 경로를 발견하지 못했다.

이제 입력을 마칠 때 조합 글자를 입력 문자열과 IMGUI TextEditor 양쪽에 반영한다. 다른 버튼이 마우스 이벤트를 처리하기 전에 조합을 확정하며, Enter/Tab, 입력칸 재클릭, 포커스 이탈도 같은 처리를 사용한다. 별도 제출 스냅샷 캐시는 제거해 이전 클릭의 이름이 남는 경로도 없앴다. 사용자가 명시적으로 글자를 지우거나 조합을 취소하는 동작은 유지한다.

macOS는 Tab을 KeyCode.Tab 이벤트와 character=9 / KeyCode.None 이벤트로 연이어 보냈다. 두 번째 이벤트가 입력칸을 다시 선택하면서 다음 J가 이름을 덮어쓰는 경로도 재현했다. 이제 확정 키의 문자 이벤트까지 소비하고 키를 놓으면 해제한다.

## 검증 범위

- 실제 시작 화면부터 두벌식 입력: `ㅇㅇ` 바로 시작, `유리카` 바로 시작, 직업 선택 후 시작, 직업 선택 후 이어쓰기, Enter → E, Tab → J, 입력칸 재클릭 후 이어쓰기, 마지막 글자 Backspace 삭제.
- 직업 선택과 Enter/Tab으로 입력을 마치는 네 경우는 저장 결과뿐 아니라 시작 전 입력 문자열과 TextEditor 값도 일치하는지 확인하고 스크린샷을 남긴다.
- 공통 키보드 메뉴 회귀 검사: 16개. 기존 네이티브 키 이벤트 처리 개선도 포함한 현재 소스를 검사했다.
- 사용자 저장 데이터와 별도 테스트 저장 키를 사용한다. 입력 소스는 검사 후 원래 값으로 복원한다.
- 이번 입력 수정과 관계없는 전투·음악 전체 검사는 반복하지 않는다.

재실행: `python3 Tools/Verification/verify_name_input.py /absolute/path/WitchMoonlitForest.app /absolute/path/results`

macOS 접근성 권한이 필요하다. 검사 중 테스트 창을 사용하지 않는다. 다른 앱이 전면으로 바뀌면 마우스 입력을 중단한다.

최종 결과: 실제 한글 입력 8개 경로의 16개 검사 + 메뉴 회귀 검사 16개, 총 32개 통과. 실행 오류 0개, Unity 빌드 오류·경고 0개, 별도 셰이더 오류 0개.
