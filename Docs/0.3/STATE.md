## 2026-11-22 · 아이폰 새 게임 프롤로그 종료 조사

- 사용자 증상은 새 게임 프롤로그 시작 시 종료. 원인 후보 1순위는 원화 디코딩·화면 합성·대평원 배우 준비가 겹치는 동안의 순간 메모리 부족이다. 해당 아이폰의 종료 기록과 수정 후 실기기 결과는 아직 없다. 11월 20일 자료의 615MB는 PC 엔진 텍스처 추정치다.
- 수정 전 `ea563a9`의 로고 단계에서 원화 6장에 `decode()`를 호출하고 모두 모듈에 보관하는 것을 계측했다. 원본 픽셀을 RGBA 1벌로 계산하면 36.01MiB다. 수정 후 프롤로그 그림은 현재·전환용 두 자리(약 12MiB 상당), 종료·취소 시 DOM 참조 0개다. 브라우저 자체 캐시나 합성 메모리는 이 계산에 포함되지 않는다.
- 아이폰·아이패드는 원화 해상도, 카메라 확대와 자막을 유지하면서 실시간 흐림 복제와 배경 블러를 줄였다. 로고/타이틀의 예비 곡 디코딩과 배회 몬스터 선준비를 생략하고, 습격 늑대 준비 뒤 말·마차를 읽는다. 즉시 건너뛰거나 소환이 지연돼도 기존 시간 제한으로 진행한다.
- 지연된 GLB 로더를 사용해 새 게임에서 첫 플레이 프레임까지 호출을 비교했다. 말·마차 합계 4회에서 2회로 줄었다. 준비 중인 인스턴스를 같은 맵·장면의 첫 프레임에 인계하며 다른 맵이나 타이틀 복귀 때 해제한다. NullEngine 모형을 4회 준비·해제한 뒤 장면 자원과 관찰자 수가 기준으로 돌아왔다.
- 검증은 관련 Node 테스트 46개와 0.3 Vite 번들 및 런타임 모듈 검사까지다. 실기기 검수 지점은 새 게임 첫 그림, 건너뛰기, 마차 탑승 장면, 첫 늑대 전투다. 재발 시 성능 기록의 `previousRun.trail`에 원화 컷, 늑대 준비, 마차 준비가 남는다. 같은 시각의 iOS JetsamEvent 또는 WebKit 종료 기록과 대조한다.
