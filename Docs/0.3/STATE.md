- 순서 변경: 00:50 항목의 ③(텍스처)을 먼저 했다. 이유: 폰 기록에서 "이동 · 모델 준비" 끊김 구간 안에서 텍스처 올리기 횟수가 함께 늘었다(322~329초에 5회). ①지형 조각 나눠 켜기, ②셰이더 메시 이름 기록은 아직 안 했다.
- 구조: `src/split-texture-upload.js`(공용, 지역·자산 목록 없음). KTX2 올리기 한 곳(`map-texture-lifetime.js`의 `_createTexture` 래퍼)에서 **최상위 단계가 1MB 이상**이면 이 경로로 간다. 2048 이상 압축 텍스처 전부(현재 2048 99장, 4096 75장, 8192 2장)와 앞으로 추가될 지역에 자동 적용.
- 방식: `texStorage2D`로 저장소를 잡고, 작은 단계(256KB 이하)는 즉시, 큰 단계는 4x4 블록 줄에 맞춘 가로 띠로 프레임당 예산만큼 올린다(폰 1MB, PC 4MB, 로딩 중 16MB). **마지막 띠가 올라간 뒤에만 로드 완료를 알린다**(`_uploadAsync` 래퍼가 기다림) → 흐린 중간 상태가 화면에 나오지 않고, 스트리밍 텍스처는 그때까지 기존 것을 유지한다. 화질 변화 없음.
- 맵 이동·모달 중에는 렌더 루프가 멈춘다(`frameLoop.setPaused`). 프레임이 100ms 넘게 없으면 타이머가 16MB씩 마저 올린다(로딩이 멈추지 않게). 대기 중 해제된 텍스처는 버리고 로드를 취소로 끝낸다. 컨텍스트 손실 시 대기열을 비운다(Babylon이 복구 때 다시 올림).
- 기기가 띠 올리기를 거부하면(형식별로 임시 텍스처에 1회 확인) 기존 Babylon 경로를 쓴다. 0.3에서만 켠다. `?splitupload=0`으로 끈다.
- 알아 둘 것: Babylon 9.31의 `_uploadCompressedDataToTextureDirectly`는 밉맵이 있는 텍스처에 이미 `texStorage2D`+`compressedTexSubImage2D`를 쓰고 `_hardwareTexture.memoryAllocated`에 기록한다. 형식 확인 코드가 이 플래그를 건드려 텍스처가 검게 나오는 버그를 실제 Babylon 검사에서 잡아 고쳤다.
- 확인한 것: 단위 테스트 7개(가짜 GL), 관련 KTX·텍스처 스트리밍 테스트 14묶음 통과. 헤드리스 크롬(SwiftShader, BC7) + 실제 Babylon 9.31 + 실제 4096·2048 KTX2: 기존 방식과 화소 차이 0(전체·1:1 확대, sRGB·선형), GL 오류 0, 4096 한 장 = 띠 21개·프레임당 1MB, 루프 정지 시 타이머로 완료, 대기 중 해제 시 버림.
- 확인 못 한 것: 폰(ASTC, Mali/Adreno)에서의 실제 시간과 띠 올리기 지원 여부, 게임 전체 화면, 왕복 누수 검사(`leak-probe.mjs`는 GL이 없어 이 경로를 지나지 않는다 — 배포 전에 브라우저에서 확인 필요).
- 검증 기준(새 폰 기록): `ktxUploads`의 `cpuMs` 최댓값 60ms → 5ms 이하, `metadata.splitUpload`의 `maxPumpMs`(프레임당 띠 올리기 시간)·`unsupported`(0이어야 분할 경로 사용 중), 60ms 이상 프레임 수(115개) 비교.
