아래 수치는 제어된 Node/NullEngine 검사와 CPU 작업 횟수입니다. 모바일 FPS 향상률이나 발열 감소, 200ms 지연 완전 제거를 측정한 결과가 아닙니다. 줄인 경로와 남은 문제를 구분했습니다.

1. 정지 전투 중 풍경 전체 재검사 제거

기존에는 같은 카메라에서도 250ms마다 기본 배치 전체를 검사했습니다. 이제 투영과 상태가 같으면 동일한 후보·순서·화면 점유율 결과를 재사용합니다. 체류 시간·승격·해제의 기존 시계는 계속 진행합니다.

카메라·활성/행렬·장면 추가/제거·모델/LOD·실패/재시도·컷씬 거리 변경은 무효화합니다. 편집·사용자 스트림은 직접 검사를 유지합니다. 카메라가 계속 움직이는 구간의 검사까지 없앴다는 뜻은 아닙니다.

2. 맵 셰이더 준비의 공유 작업 예산 우회 수정

모든 대기 서브메시의 SDK 준비 검사를 한 번에 실행하던 경로를 기존 준비 예산에 연결했습니다. 같은 메시·서브메시의 중복 입력도 제거했으며 다른 재질/스킨/모프/인스턴싱·그림자 조건은 그대로 검사합니다.

합성 24건 × 0.6ms 사례: 한 작업 14.4ms → 준비 기회당 최대 2.4ms. 준비된 저비용 검사 1,000건은 4회 기회로 처리해 250프레임 대기를 만들지 않습니다. 마지막 SDK 검사 비용도 반환 전에 공유 예산에 반영합니다.

단일 SDK/GPU 호출은 중간에 자를 수 없습니다. 위 분할 수치는 총 CPU 작업 감소나 실제 GPU 시간 감소와 다릅니다. 새 렌더 패스·상시 폴링은 없습니다.

3. 공용 모델 컬링의 중복 검증·행렬 조회 제거

갱신된 경계 한 번에서 소스/모프 검증과 월드 행렬 조회가 각각 2회 → 1회가 됐습니다. 같은 동기 함수 안에서 검증한 행렬만 재사용합니다.

다음 질의의 같은 프레임 뼈/모프 변경, 행렬 콜백 변경, 지원 불가 시 표시 유지, 본체/외곽선 일치, 카메라 밖 그림자와 풀 재사용 계약은 보존했습니다. 전체 모델 비용이 절반이 됐다는 뜻은 아닙니다.

4. 길찾기마다 큰 임시 배열을 생성·초기화하던 비용 제거

A* 점수·부모·닫힘 상태를 navigator별 한 작업 공간에서 재사용합니다. 세대 표식으로 이전 검색을 구분하여 경로마다 전체 지도의 점수를 채우지 않습니다. 기존 노드·간선·동점 우선순위·경로와 충돌 결과는 유지합니다.

제어된 1,681노드/100회 사례: 검색 버퍼 생성 300회 → 4회, 누적 할당 2,185,300B → 33,620B. 재사용을 위해 33,620B가 남습니다. 실제 지도에서는 가장 큰 검색 크기까지 한 세트만 보존하며, 노드/간선/힙/최종 경로 메모리는 이 수치 밖입니다.

아직 남은 성능 과제

  • 실제 모바일의 지속 FPS·발열과 긴 GPU/드라이버 대기 원인 구분.
  • 긴 단일 텍스처·모프·버퍼 업로드와 여러 로더의 자원 입장 통합.
  • 전체 자원 상주·휴면 풀의 통합 예산, 추가 지형 분할·정적 배경 묶기.
  • 추가 반경의 최초 길찾기 격자 생성은 여전히 동기 작업. 이번 변경은 반복 검색 버퍼에 한정.
  • 캐시 맵 이동·첫 등장 시간과 진단 기록 ON/OFF의 실기기 비교.

이번 수정은 성능 진단을 켜야만 작동하는 기능이 아닙니다. 일반 플레이의 동일 경로에 적용됩니다.
