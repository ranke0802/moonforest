MoonForest 상용 출시까지의 계획

내 코드베이스라면 이렇게 진행하겠습니다. 시놉시스 전체를 한 번에 완성하지 않습니다. 1장(전사 편)과 2장(엘레나 편)을 묶어 「에피소드 1」을 상용 품질로 먼저 출시합니다. 그 과정에서 만든 제작 틀(배우·지역·전투·컷씬·대화 템플릿)로 3~6장을 이어 갑니다. 토큰은 같은 것을 다시 읽고 다시 보고하는 데 가장 많이 새고 있으므로, 작업 방식부터 바꿉니다.

1. 현재 위치를 다시 재기

"70%"는 기술 기반 기준으로는 맞고, 전체 이야기 기준으로는 아닙니다세 가지 축으로 나눠 봐야 다음 우선순위가 보입니다
축체감 진척(추정)근거
엔진·도구·수명 관리약 70~80%맵 4개 스트리밍, 셰이더 사전 준비, 자원 수명, 배치·몬스터·컷씬·스토리보드 편집기, 0.1/0.2 분리 배포, 저장 복구가 있습니다. 남은 것은 개체 등급 갱신, 풍경 묶음 제출, 통합 자원 예산입니다.
1장 콘텐츠(전사 편)약 50~60%메인 M00~M09, 의뢰 Q01~Q09, 곰·늑대 4종·여우·멧돼지·고블린·엘레나 2단계가 있습니다. 홉고블린·구울·반려동물 이벤트(Q03/Q08/M06)는 미구현이고, 게임에 연결된 컷씬은 0건입니다(cinematic-registry.json의 entries가 비어 있음). 꿈 도입, 비비앙 개입, 일지 엔딩 연출이 없습니다.
시놉시스 전체(1~6장·에필로그·비비앙 편)약 10~15%2장 플레이어블 엘레나(성녀 키트와 흑마법 키트 두 벌), 요아힘, 왕국 거점, 특임대, 마왕성, 장군들, 드라카리, 교황, 마하칼리, 성검 회귀 시스템, 비비앙 캠페인이 모두 미착수입니다.
1장2장3장4장5장6장결

막대는 장별 제작 분량의 대략적 비중입니다. 신규 지역·보스·플레이어블 수로 가늠했으며 측정값은 아닙니다.

이 차이를 인정하는 것이 계획의 출발점입니다. 지금 방식(기능 하나마다 긴 검증과 HTML 보고서)으로 3~6장까지 가면 토큰과 시간이 감당되지 않습니다. 따라서 먼저 에피소드 1 범위로 출시 목표를 좁히고, 제작 단가를 낮추는 작업을 콘텐츠 제작보다 앞에 둡니다.

2. 제품 정의: 무엇을 먼저 팔 것인가

에피소드 1 = 1장 전사 편 + 2장 엘레나 편두 시점이 한 사건을 마주 보는 구조가 이미 완결된 하나의 이야기
  • 왜 1+2장인가: 2장이 끝나면 "전사가 상대했던 마녀가 무엇을 지키려 했는가"가 닫힙니다. 출시 단위로 충분한 감정적 결말이 있고, 3장(마왕성·성검)은 자연스러운 다음 에피소드 예고가 됩니다.
  • 재사용 효율: 2장의 무대는 같은 마을·숲·동굴의 과거 시점입니다. 새 맵 대신 시간대·소품·주민 배치·조명만 바꾸면 됩니다. 신규 아트 비용이 가장 낮은 확장입니다.
  • 분량 목표(제안): 첫 플레이 5~7시간. 1장 3~4시간, 2장 2~3시간. 보스 6종(곰, 고블린 주술사 무리, 홉고블린, 엘레나 인간형·마물형, 2장 최종: 마물 습격 또는 가해자 일당). 현재 늑대·곰의 전투 밀도를 기준으로 추정했습니다.
  • 비비앙 편은 시놉시스 구성 메모대로 선택 캠페인입니다. 에피소드 2 이후로 미룹니다.
  • 성검 회귀는 에피소드 2(3장)의 핵심 시스템이지만, 게임 상태 구조를 좌우하므로 기술 시제품만 1단계에서 만듭니다(6절).

결정이 필요한 것 (사용자 판단)

질문내 추천이유
출시 플랫폼PC 웹/스팀(데스크톱 래핑)을 먼저, 모바일 웹은 같은 빌드의 품질 프로필로이야기 중심의 프리미엄 게임은 PC 구매층이 맞고, PC에서 그래픽 축소를 되돌릴 여유가 있습니다. 모바일은 성능 인증 비용이 큽니다.
판매 방식에피소드 1 유료(또는 1장 무료 체험 + 2장 포함 정식판)1장만으로 체험판, 2장 해금이 구매 동기가 됩니다.
2장 엘레나 조작성녀 키트 3~4기술 + 흑마법 키트 3~4기술, 전사보다 작은 규모두 키트를 전사급으로 만들면 2장이 1장보다 비싸집니다.
도입부마차 대신 여관(3절)제작비가 낮고, 이후 시스템과 연결됩니다.

3. 도입부: 마차 대신 마을 여관

추천: "여관 2층 방에서 꾸는 꿈"으로 시작마차 이동 연출 없이 같은 꿈과 같은 편지를 전달하고, 여관이 이후 거점이 됨
  1. 밤, 여관 방: 전사가 늦게 도착해 잠듭니다. 시놉시스의 꿈(치유하는 손, 청년, 습격, 응답 없는 기도, "그 아이를 찾아라")은 1분 컷씬으로 그대로 씁니다.
  2. 깸: 마부의 대사를 여관 주인으로 바꿉니다. 예: "밤새 앓는 소리를 내더군. 아침은 차려 뒀네." 전사가 교회의 편지를 꺼내 임무를 확인합니다.
  3. 1층 식당 = 첫 대화 튜토리얼: 주인과 손님에게 엘레나의 소문을 듣습니다. 증언 수집 구조(M01)를 안전한 실내에서 먼저 익힙니다.
  4. 문 밖 = 마을: 기존 마을 맵으로 바로 연결됩니다. 대평원 삼거리(M00)는 "약초 의뢰로 처음 마을 밖에 나가는 길"로 바꿔 2~3번째 퀘스트에 둡니다.

마차보다 나은 이유

  • 제작비: 움직이는 마차, 길 위 카메라, 정차지 연출이 필요 없습니다. 실내 방 하나와 식당 하나면 됩니다(기존 마을 집 자산과 소품 재사용).
  • 시스템 연결: 여관은 휴식·저장·회복, 소문(증언) 수집, 의뢰 게시판이 모이는 거점이 됩니다. 3장 성검 규칙의 "전투 밖 안정된 장소에서 귀환 기록 봉인"과도 자연스럽게 이어집니다.
  • 2장 대칭: 2장의 엘레나도 같은 여관(과거 시점)을 드나들며 요아힘과 시간을 보냅니다. 같은 공간이 두 시점에서 다른 의미를 갖습니다.
  • 성능: 첫 화면이 실내라 로딩 중 무거운 대평원을 준비할 시간이 생깁니다.

대안: 마을 교회의 빈 숙소에서 시작하는 방법도 있습니다. 엘레나가 쓰던 방이라면 첫 장면부터 단서를 줄 수 있지만, 교회 소속감이 강해져 "교회의 명령만으로 움직이지 않는 전사"라는 개정 방향과는 조금 어긋납니다.

4. 단계별 진행 계획

기간은 사용자 1인 + Claude 기준의 거친 추정입니다. 각 단계는 사용자 검수 게이트를 통과해야 다음 단계로 넘어갑니다.

0단계 · 정리와 기준 세우기 (1~2주)이후 모든 작업의 비용을 낮추는 단계. 콘텐츠는 만들지 않음
  1. AGENTS.md 다이어트: 현재 68KB이며 매 세션 통째로 읽힙니다. 핵심 규칙 8KB 이하로 줄이고, 종별·기능별 상세는 Docs/rules/*.md로 나눠 필요한 작업에서만 읽게 합니다. 가장 큰 토큰 절감 항목입니다.
  2. 그래픽 축소 목록 작성: 그동안 성능 때문에 줄인 것을 한 표로 모읍니다. 승인 원본과 런타임 사이의 삼각형·텍스처·그림자·외곽선 예산·시야·효과를 정리하고, 각 항목에 "PC에서 복원 / 모바일 유지 / 구조 개선 후 복원" 중 하나를 표시합니다.
  3. 품질 프로필 3단계 정의: 모바일 표준, 모바일 고급, PC 고급. 지금은 한 설정을 모든 기기가 공유하고 있어 PC가 모바일 수준에 묶여 있습니다.
  4. 고정 벤치마크 모드(검토 보고서 E6): 이후 모든 성능 판단의 기준입니다.
  5. 작업 트리 정리: 미추적 798개 항목과 미승인 음원 배포 목록을 정리합니다. 무엇이 실제 입력인지 명확해야 에이전트가 덜 헤맵니다.
  6. 에피소드 1 범위 문서: 1·2장의 장면 목록, 퀘스트, 보스, 신규 자산 목록을 한 표로 고정합니다(6~8쪽 분량).

게이트: 축소 목록과 범위 표를 사용자가 승인.

1단계 · 기술 기반 완성 (3~4주)콘텐츠를 늘려도 느려지지 않는 구조. 성검 회귀의 전제 조건도 여기서 정함
  1. 배우 표현 등급: 존재하는 수와 고비용 처리 수를 분리합니다(검토 보고서 P1·6절).
  2. 원거리 풍경 묶음 제출: 시범 후 확대합니다(P2).
  3. 통합 자원 예산: 소유자별 예산을 하나로 합칩니다(P4).
  4. PC 고급 프로필 1차 복원: 그림자 2048~4096, 외곽선 예산 확대, 블룸·색보정 LUT, 풍경 밀도 복원. 모바일 경로는 건드리지 않습니다.
  5. 컷씬 실연결: 스튜디오는 있지만 게임 등록 0건입니다. 여관 꿈 컷씬 하나를 끝까지 연결하면서 파이프라인(작성 → 검증 → 등록 → 재생 → 건너뛰기 → 복귀)을 확정합니다.
  6. 대화·증언 데이터 형식: 퀘스트 데이터(chapter-quest-data.js)처럼 대화와 증언도 데이터 파일로 만듭니다. 이후에는 Claude가 코드 대신 데이터를 쓰게 됩니다.
  7. 스냅샷 가능한 게임 상태(회귀 시제품): 플레이어·배우·투사체의 상태를 10초 고리 버퍼에 저장하고 되돌리는 최소 시제품을 만듭니다. 출시용이 아니라 "이후 만드는 모든 시스템이 되돌릴 수 있는 형태인지"를 확인하는 기술 검증입니다. 늦게 발견하면 3장에서 대규모 재작업이 됩니다.

게이트: 벤치마크 19마리 구성에서 모바일 CPU 작업 목표(예: 16ms 이하)를 확인하고, PC 고급 화면을 사용자가 승인.

2단계 · 골든 슬라이스 (4주)여관 꿈 → 마을 → 평원 → 곰까지 30~40분을 "출시 품질"로

이 구간이 상품의 첫인상이자 품질 기준표가 됩니다. 여기서 정한 수준을 이후 모든 구간의 합격선으로 씁니다.

  • 아트: 배우 조명 응답(검토 G2), 배경 반복감 완화(G4), 시간대(밤 → 아침), 실내 조명.
  • 연출: 꿈 컷씬, 첫 마을 진입 카메라, 곰 등장 연출, 곰 처치 후 마을 반응.
  • 전투 손맛: 히트스톱, 타격 섬광, 카메라 흔들림, 곰 전조 표시를 효과 예산 안에서 다듬습니다.
  • 소리: 마을·평원 환경음, 여관 실내음, 곰 전투 음악(승인 절차 유지).
  • UI: 전투 중 퀘스트 패널 축소, 최소 글자 크기, 첫 10분 안내(조작·방어·회피).
  • 저장: 여관 휴식 저장과 자동 저장, 실패 시 명확한 표시.

게이트: 사용자가 처음부터 끝까지 직접 플레이하고 "이 품질로 팔 수 있다"고 판단. 가능하면 지인 3~5명의 외부 플레이 피드백.

3단계 · 1장 완성 (6~8주)골든 슬라이스의 틀로 나머지 1장을 채움
  • 고블린 습격: 방패병·궁수·주술사 역할 분담. 고블린 원형과 보유 자산을 재사용합니다.
  • 마물의 숲·홉고블린: 마석 강화와 칭호 도입. Q03/Q08/M06의 미구현 사유를 해소합니다.
  • 동굴 실험실: 구울 전사, 기관장치, 기록 수집.
  • 타락의 성소: 기존 엘레나 2단계 보스를 이야기 연출과 연결합니다.
  • 비비앙 개입과 남겨진 방·일지 엔딩 컷씬.

제작 방식: 신규 몬스터 하나는 "자산 등록 → 동작 목록 → 공격 접촉 → 등급 갱신 → 검수 HTML 1장"의 고정 순서로 만듭니다. 늑대 제작 때처럼 R1~R16까지 반복되지 않도록, 사용자 검수는 동작 목록 단계에서 한 번, 게임 연결 후 한 번으로 제한합니다.

게이트: 1장 처음부터 끝까지 막힘 없이 클리어, 진행 불가 버그 0, 사용자 승인.

4단계 · 2장 엘레나 편 (6~8주)같은 무대의 과거 시점 + 새 플레이어 키트
  • 과거 시점 상태: 마을 배치·주민·조명·소품을 시간대 데이터로 전환합니다. 무너진 목책이 없는 마을, 살아 있는 요아힘, 건강한 숲.
  • 엘레나 플레이어 키트: 성녀 시절(치유·보호막·정화)과 흑마법(저주·소환·지배). 기존 엘레나 모델과 동작을 재사용하되, 플레이어 조작용 입력과 판정을 새로 만듭니다.
  • 요아힘 동료 AI: 함께 싸우는 경험이 2장의 핵심입니다. 동료 AI는 3장 특임대와 5~6장 동료 연계의 기반이 됩니다.

토큰이 새는 곳과 막는 방법현재 작업 기록을 보면 구현보다 확인·보고·재독에 더 많이 쓰고 있음
새는 곳 (관측)바꿀 방식
68KB AGENTS.md를 매 세션 읽음8KB 핵심 + 주제별 파일. 작업 지시에 "읽을 규칙 파일"을 명시
작업마다 장문 HTML 보고서와 검증 JSON작업 단위는 CHANGELOG.md에 5줄. HTML 보고서는 단계 게이트에서만

  5. 보고: 바뀐 것 / 확인한 것 / 확인 못 한 것, 각 한 줄

7. 위험과 대응

계획을 무너뜨릴 수 있는 것 6가지
  • 범위 팽창 높음: 시놉시스가 6장 규모입니다. 에피소드 1 범위표에 없는 기능은 "다음 에피소드"로 자동 이월하는 규칙을 둡니다.
  • 아트 제작 속도 높음: 신규 보스·NPC 모델이 병목입니다. 에피소드 1에 필요한 신규 모델(홉고블린, 구울, 요아힘, 주민 몇 명, 과거 엘레나 의상)을 0단계에서 확정하고, 외주나 생성 도구 사용 여부를 먼저 정합니다.
  • 회귀 시스템의 구조 부채 중간: 1단계 시제품으로 일찍 확인합니다.
  • 모바일 성능 인증 중간: 출시 플랫폼을 PC 우선으로 두면 위험이 줄어듭니다.
  • 민감한 서사 표현 중간: 2장의 폭력·마비침 장면은 연령 등급과 스토어 심사에 영향을 줍니다. 생략 연출 원칙을 유지하고 출시 전 등급 기준을 확인합니다.
  • 권리 문제 중간: BGM·음원 출처 검토가 이미 한 번 문제가 되었습니다. 출시 전 모든 외부 자산의 라이선스 목록을 확정합니다.
