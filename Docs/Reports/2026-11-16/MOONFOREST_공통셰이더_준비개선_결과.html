문제공통 수정
준비와 실제 배치 방식 불일치실제 Babylon 배치·추가 인스턴스 버퍼 조건과 예정된 배치를 구분합니다. 배우는 지원되는 불투명/사망 및 인스턴싱 변형을 준비하고 현재 사용할 조건을 마지막에 둡니다.
재질·패스 누락메시 대표 재질만 보던 코드를 하위 재질별 확인으로 변경. 카메라/출력 RTT·여러 그림자 패스·피격 오버레이를 정확히 확인합니다. 종별 메타데이터가 없는 일반 모델도 제외하지 않습니다.
frozen 재질의 잘못된 준비 완료frozen의 조기 성공을 피하고 같은 renderId에서도 실제 조건을 검사합니다. 빌린 준비 플래그·pass·투명도·frozen 상태를 복원합니다.
준비한 다른 변형의 수명준비 프로그램을 메시가 살아 있는 동안 추가 참조로 보존합니다. 메시당16개/엔진 고유128개로 제한하며 취소한 신규 준비분과 메시·장면·엔진 해제를 정리합니다. 한도 초과 시 강제 퇴출하지 않습니다.
실제 최초 자세보다 이른 준비플레이어는 최초 장면 렌더 전에 준비합니다. NPC·컷씬은 숨긴 상태에서 초기 자세와 모프를 적용한 뒤 본체·그림자·내부선을 준비하고 표시합니다. pooled 재생도 같은 순서를 따릅니다.

일반 플레이에서도 적용되는가?

적용됩니다. 기록을 켜야 동작하는 최적화 조건은 발견되지 않았습니다.

동일 NullEngine 장면을 진단 OFF / 기본 진단 / 기록 / 상세 기록 네 상태로 실행했습니다. 실제 드로 인수와 원본 반환값, 변환·가시성·재질·인스턴스 수, 렌더 크기·FPS 설정·공유 준비 예산이 동일했습니다. 계측 해제 시 원본 메서드와 관찰자가 복구되는 것도 확인했습니다.

기록을 켰을 때 더 부드럽다는 체감의 원인은 아직 확정하지 않았습니다. 설정 창에서 잠시 정지한 사이 준비가 끝나는 효과, 이미 준비된 캐시, 기기 온도/스케줄링, 측정 래퍼의 JIT·드라이버 타이밍 영향은 구분해야 합니다. 이를 이유로 평소에도 상세 계측을 강제로 켜는 우회는 하지 않았습니다.

적용 경로

  • 플레이어 최초 로딩 및 기존 일반·보스 소환 공통 경로
  • 배치 몬스터·편집 소환·게임플레이 배우를 이용하는 컷씬
  • 일반 NPC·시각 전용 컷씬의 초기 자세와 공유 내부선
  • 기존/스트리밍/편집 배경의 하위 재질 준비, 독립 퀘스트 표식의 실제 비인스턴싱 조건

향후 이 프로젝트의 공통 로더/adapter를 통해 넣는 모델도 같은 기준을 사용합니다. 공통 경로를 거치지 않는 새로운 별도 렌더러에는 자동 적용됐다고 간주하지 않도록 AGENTS.md에도 연결했습니다.

검증과 보존

통합 검사125개와 별도 네 맵·외곽선·안개·내부선·준비 관련43개 검사가 통과했습니다(일부 중복). 마을·대평원·숲·동굴 왕복의 수명/취소 관련 검사와 실제 전사·성녀·마녀·늑대·곰 준비 검사도 포함합니다. 원본 지오메트리·골격·인덱스·스킨 가중치를 유지한 것을 확인했습니다. 0.2 빌드/동기화와 리소스 그래프 보존을 확인했습니다.

배우 검사 중 발견한 오래된 테스트 기준은 현재 일반 4족 모델의 버전/추가 클립과 승인된 시체10초에 맞췄습니다. 게임의 버전·모션·소멸 시간을 바꾼 것이 아닙니다.

남은 한계

Node/NullEngine은 실기기 GPU 성능 검증이 아닙니다. 최초로 필요한 SDK 컴파일 호출은 중간에 끊을 수 없으므로 공유2ms 예산이 실제2ms 상한이라는 뜻도 아닙니다. 이번 수정은 준비 누락과 불필요한 재생성 경로를 줄인 것이며, 과거 모든200ms 멈춤·후반 지속 FPS 저하·캐시 로딩45초 시간초과가 해결됐다고 판정하지 않았습니다.

성능 진단 JSON의 preparedShaders에서 보존 중 프로그램/소유자/한도 거부 수를 확인할 수 있습니다. 참조 개수이며 GPU 메모리량이 아닙니다. 이 통계 수집 여부와 준비 최적화 실행 여부는 분리되어 있습니다.
