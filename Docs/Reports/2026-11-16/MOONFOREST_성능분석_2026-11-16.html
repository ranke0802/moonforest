상세 호출로 확인된 원인

사전 준비와 실제 렌더링의 INSTANCES 모드가 다릅니다.

현행 boss-shader-warmup.js:30은 준비 시 isReadyForSubMesh(...,false)를 사용합니다. 반면 느려진 늑대/곰 셰이더의 실제 로그는 INSTANCES=true입니다. 준비 범위에 빈틈이 있는 것은 코드와 로그 양쪽에서 확인했습니다. 모든 멈춤의 원인이 이것 하나라고 확정한 것은 아닙니다.

텍스처·후보 선별·메모리의 해석

  • 수집한 KTX 업로드 16회는 동기 CPU 호출 최대 1.0ms입니다. 느린 이벤트 643개 중 텍스처 상태 idle은 639개입니다. 업로드만으로 모든 지연을 설명하기 어렵습니다. 이후 GPU 작업은 이 CPU 시계로 배제할 수 없습니다.
  • 125.68초 늑대 소멸 프레임은 activeMeshes 4.6ms, 실제 후보 함수 약 0.6ms에 비해 drawSubmission이 127.5ms입니다. 이 사건은 후보 수보다 셰이더 준비가 더 직접적인 원인입니다.
  • 306초 주변에서는 activeMeshes 26.9~30.2ms, 플레이어 애니메이션 62.4ms, 풍경 수요 검사 14.8ms가 인접 프레임에서 함께 상승합니다. 단일 병목보다 GC·스케줄링·기기 속도·반복 할당도 검토할 구간입니다. GPU 시간은 unsupported여서 확정할 수 없습니다.
  • 플레이어 바인딩은 408→75,888개 생성 누적, 재사용 49,368개, 교체 183회이며 현재 보유는 1,224개입니다. 약 7.5만 개가 계속 메모리에 남아 있다는 뜻이 아닙니다. 재생성/폐기의 반복 비용은 남아 있습니다. 늑대 두 개체는 새 바인딩 생성 0으로 기록됐습니다.
  • 마지막 JS heap 약 139MB, Mesh 3,029→3,090, Skeleton 2→7입니다. 적 추가와 캐시가 포함되므로 이 두 시점만으로 누수를 확정할 수 없습니다. 현재 데이터에는 온도·주파수 측정이 없습니다.

로딩에도 별도 문제가 남아 있습니다

캐시가 있는 대평원 첫 준비가 49.20초 뒤 model 단계 시간초과로 실패했고, 재시도는 8.17초에 완료됐습니다. 재시도 내역은 준비 15ms + 다운로드/캐시 확인 1.93초 + 모델 5.11초 + 화면 1.12초입니다. 네트워크 다운로드는 0바이트입니다.

마지막 Meshopt 요청은 대기 966.2ms / 실제 decode 20.3ms, KTX 요청은 초기화 65.7ms / decode 182.4ms입니다. 이것만으로 앞선 45초 시간초과의 대상을 특정할 수는 없지만, 재다운로드보다 큐·캐시 조회·모델 준비 경로를 봐야 할 근거입니다.

수정 우선순위

  1. 사전 셰이더 준비 보완: 실제 본체·투명 사망·인스턴스·스킨·morph·렌더 패스 조합과 맞추고, 준비된 프로그램의 유지/교체를 확인합니다. 살아 있는 모델을 모두 투명 재질로 바꿔 우회하지 않습니다.
  2. 캐시 로딩 시간초과와 큐: 어떤 파일/디코더/준비 장벽이 45초를 점유했는지 기존 수명 정보와 연결하고, 반복 캐시 조회와 큐 대기를 줄입니다.
  3. 후반의 지속 CPU 부담: 약 19~21ms까지 올라간 분 단위 CPU 작업과 전사 동작 전환 할당을 줄입니다. 시야 품질·해상도·LOD를 추가 감량하는 것을 우선 답으로 삼지 않습니다.
  4. 미확정 렌더 정체: 207.72초와 엘레나 사망 프레임은 호출 상세가 없으므로 다른 사건의 셰이더 원인을 그대로 복사하지 않습니다.

분석 중 게임 소스·배포본을 변경하지 않았으며 브라우저 자동조작도 사용하지 않았습니다. 추가 실기기 테스트를 요청하지 않고 현재 로그와 코드에서 확인한 범위로 구분했습니다.
