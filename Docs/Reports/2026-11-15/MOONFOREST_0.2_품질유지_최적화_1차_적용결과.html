  2. 압축 모드에서 시작에 실패하면 오류 화면의 8K 원본으로 다시 불러오기로 수동 복구할 수 있습니다. 실패 후 두 그래프를 자동으로 중복 다운로드하지 않습니다.

  4. 기존 성능 진단의 JSON에는 preparationBudget과 reviewEffects 상태가 추가됩니다. 평소 상세 CPU 추적·GPU 동기 대기를 추가로 켜지 않습니다.

구간변경보존·한계
PC 텍스처기존 8K UASTC KTX2 그래프를 0.2 PC 기본 선택으로 연결. 사용자 원본 선택과 오류 화면 복구 제공.8K/4K/2K 원래 해상도, 모델·UV·골격·모션 데이터 유지. GPU 블록 압축의 미세한 색상 차이는 가능. 모바일의 기존 4K 압축 / 2K RGBA 선택 유지.
풍경 계산자산별 배치 인덱스, 기본 맵의 준비 완료 상태, 동일 카메라·경계구의 정확한 투영값을 재사용.거리·LOD 단계·대평원 배율·선택 공식 유지. LOD 해제·실패/재시도·자산 교체·명시적 편집 변경을 감지. 일반 편집 스트림의 직접 검사 유지.
공통 준비 예산증분 배치와 배우/셰이더 준비 경계가 장면별 2ms 목표를 공유. 같은 대기 기회가 예산을 중복 초기화하지 않음.단일 SDK 호출을 중간에 끊는 상한이 아님. 기존 취소·세대·시간초과·순서·준비 장벽 보존. 모든 텍스처 업로드가 이미 통합된 것은 아님.
효과 검수 기반화염 형상·섬광·확산 링·불씨를 한 메시로 재생. 유한 슬롯·밀도/면적 압력 제어, 이벤트 때만 버퍼 갱신. 맵/플레이어 재로딩 시 비움.별도 광원 0, 반사/내부선 RTT 0, 추가 RAF 0. 기존 동굴 안개 가림 재사용. 처음 누를 때만 모듈·버퍼 준비. 실제 전투의 예고/명중/피해는 변경하지 않음.

KTX2를 고려한 메모리와 다운로드 구분

전사 6개 이미지의 원래 크기를 유지한 채 8bpp 압축으로 추정하면 832 → 약 208MiB, 약 624MiB 감소 여지가 있습니다. 위쪽 두 8K만 비교하면 682.67 → 170.67MiB입니다. 기기·디코더의 실제 선택 형식과 작업 메모리는 별도입니다.

137삼각형이 쓰는 큰 아틀라스 조사

사용 영역은 작은 UV 조각들이 8K 전체에 흩어져 있습니다. 단순 사각형으로 자르면 면적의 92.61%가 남고, 2의 거듭제곱 크기는 계속 8192입니다. 따라서 단순 crop의 이 방식 GPU 절감은 0입니다. 이 결과를 무시하고 UV를 자동으로 바꾸지 않았습니다. 조각별 재배치·패딩·mip 이음새 비교를 거친 별도 후보가 필요합니다.

확인한 범위

PC 선택/설정 12개, 실제 두 리소스 그래프의 모델·UV·애니메이션·sampler 동등성과 KTX2 해상도 1개, 공유 준비 16개, 풍경/마을·대평원·숲·동굴 관련 회귀 25개, 효과 예산·수명·지연 완료·설정 연결 7개를 확인했습니다. 0.2 빌드와 동기화가 통과했고 공유 리소스 그래프 및 동결한 0.1 목록을 유지했습니다.

브라우저 자동조작은 사용하지 않았습니다. Node/NullEngine 검사는 실제 GPU의 GLSL 실행·화질·실기기 FPS/발열 검수를 대신하지 않습니다. 과거 200ms 드라이버 지연이 완전히 사라졌다고 판정하지 않았습니다.
