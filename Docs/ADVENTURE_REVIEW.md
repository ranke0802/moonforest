# v4.15 · 모험 진행과 기본 시점

v4.14와 실행 계획을 먼저 `17f8baa`로 GitHub에 보관한 뒤 진행했다. 로컬 확인 빌드 A(입력), B(첫 의뢰), C(보상·후속 의뢰), D(통합)를 거쳐 최종 v4.15 실행 앱을 만들었다.

## 반영 내용

- 캠프 루미의 의뢰 → 지정 적 4마리 → 오염 지점 2곳의 호위 처치·정화 → 보스 앞 쉼터 → 고정 공터의 달늑대로 연결했다. 처치 수만으로 보스가 나타나는 기존 방식은 일반 모험에서 사용하지 않는다.
- 현재 목표 하나, 미니맵 금색 목적지와 E 상호작용 안내를 한국어·영어·일본어로 표시한다.
- 보스 처치 후 저주가 풀리는 빛·대화·음악 전환과 유물 선택을 제공한다. 약초 3곳 회수와 정예 꿀벌 정화 중 후속 의뢰를 고르며, 두 의뢰 모두 완료 가능하다. 마지막에는 준비된 모험이 끝났음을 알린다.
- 공용 유물은 영구 소유하고 하나만 장착한다. 처치 후 이동 +20% 4초 / 회피 후 다음 기본공격 +30% / 처치 시 최대 MP 12% 회복. 재장착·사망·불러오기에서 임시 효과는 초기화한다.
- 의뢰 단계, 고유 처치 ID, 정화·채집 상태, 보상 수령과 유물을 저장한다. 보스 중 사망·불러오기는 전투를 초기화하고 보스 앞에서 재도전한다. 기존 보스 처치 저장은 첫 의뢰를 반복시키지 않는다.
- Esc에 전투 외 캠프 귀환을 제공한다. 주변 8m 내 생존 적, 최근 5초간 피해, 보스전 또는 차징 중에는 사용할 수 없다. H/R 테스트 키는 개발자 모드로 제한한다.
- 캐릭터 미리보기 회전을 일시정지 시간과 독립적인 마우스 입력 처리로 변경하고 확대는 고정했다. 궁수 J는 발사 대상이 사라지면 MP를 먼저 차감하지 않는다.
- 보스 재도전 시 진행 중인 공격 예고와 코루틴을 정리한다. 캠프 귀환·불러오기에 카메라 위치를 즉시 맞추고, 보스와 정화 지점을 가리는 수목 시야를 정리했다.
- 사용자 스크린샷 기준 기본 시점: pitch 29.3°, yaw 144.1°, 직교 크기 6.004, 초점 높이 0.6, 거리 14, 추적 속도 10, 회전 감도 3, 휠 속도 0.28. 이전 버전 카메라 저장값은 이 기본값으로 갱신하고, 이후 저장한 조정은 유지한다.

## 검증 방식과 범위

- `--adventure-verify`: 세 직업에서 새 게임→보스→유물→두 후속 의뢰→완료, 단계별 저장·불러오기, 중복 이벤트/보상 차단, 기존 저장 이관, 보스 재도전 및 예고 정리, 유물 기능, 스크린샷의 카메라 수치 검증. **192개 통과, 실행 오류 0개**.
- 진행 검증의 전투 처치는 실제 사망 콜백에 직접 피해를 전달한다. 세 직업의 숲길 10개 경유점 이동은 실제 CharacterController와 카메라 기준 이동 입력으로 검증했다.
- `--ux-verify`: 기존 전투 입력·시전 취소·회피 방향·접지·상태 이펙트·애니메이션 **114개 통과, 오류 0개**. 이 컴퓨터의 전투 부하 표본 평균 59.6FPS, 프레임 시간 95백분위 약 17.6ms.
- `--audio-verify`: 입력·효과음·BGM **86개 통과, 오류 0개**. 최종 빌드는 오류·경고 모두 0개.
- 의뢰/보상 화면은 세 언어로 캡처하여 확인했다. 직접 입력을 전달하는 미리보기 회전·고정 확대 검증은 통과했다. 별도의 사용자가 캐릭터 선택 드래그를 검증했다는 의미는 아니다.
- 일반 사용자에 의한 설명 없는 첫 플레이와 실제 모험 완료 시간은 아직 측정하지 않았다. 계획의 10~15분/5~8분은 검증 완료 수치가 아닌 목표다. 현재 구성은 그보다 짧게 끝날 수 있으며, 실제 플레이 피드백으로 분량·난이도를 조정해야 한다.

검증 결과 JSON은 `Docs/Verification`에 보관한다. 실행 앱은 Git에 넣지 않고 로컬 `dev/달빛숲-v4.15`로 전달한다. 일회성 지형·재질 조회 스크립트는 실행 후 소스에서 제거했다.
